# Search Engine — COMP3011 Coursework 2

A command-line search engine that crawls [quotes.toscrape.com](https://quotes.toscrape.com/),
builds an inverted index, and allows full-text search with TF-IDF ranking.

---

## Project Overview

This tool implements a complete search engine pipeline:
1. **Crawler** — crawls all pages using BFS with a 6 second politeness window
2. **Indexer** — builds an inverted index storing word frequency and positions
3. **Search** — retrieves and ranks results using TF-IDF scoring

## Usage

Run the search engine shell from the project root:
```bash

```

### Available Commands

| Command | Description | Example |
|---|---|---|
| `build` | Crawl the website and build the index | `> build` |
| `load` | Load a previously saved index from disk | `> load` |
| `print <word>` | Print the index entry for a word | `> print good` |
| `find <query>` | Find pages containing all query words | `> find good friends` |
| `suggest <prefix>` | Suggest words starting with a prefix | `> suggest fri` |
| `quit` | Exit the program | `> quit` |

## Data Structures

### Inverted Index — Dictionary of Dictionaries

```python
{
  "word": {
    "https://quotes.toscrape.com/page/1/": {
      "frequency": 3,
      "positions": [5, 23, 47]
    }
  }
}
```

This design gives:
- **O(1)** lookup by word
- **O(1)** lookup by document
- Supports frequency, positional, and TF-IDF based ranking
- Scales naturally to larger corpora

A simpler dictionary of lists was considered but rejected — it cannot support per-document statistics or realistic ranking.

## Algorithm Complexity Analysis

### Crawling
- **Time:** O(P × L) where P = pages crawled, L = average links per page
- **Space:** O(P) for visited set and page storage
- BFS ensures systematic discovery — no page is missed or visited twice

### Indexing
- **Time:** O(P × W) where W = average words per page
- **Space:** O(V × D) where V = vocabulary size, D = number of documents
- Dictionary of dictionaries gives O(1) word and document lookup

### Searching
- **find:** O(Q × D) where Q = unique query terms, D = matching documents
- Optimised by sorting query terms by document frequency ascending — rarest word intersected first, minimising intermediate result size
- IDF precomputed at O(V) startup cost, then O(1) per lookup during search
- **print:** O(D) where D = documents containing the word

## Design Decisions

### Crawler
- **BFS traversal** — ensures all reachable pages are discovered systematically
- **6 second politeness window** — respects the target website as required by the brief
- **URL normalisation** — strips query parameters, fragments, and enforces trailing slashes to prevent duplicate crawling
- **`collections.deque`** — O(1) popleft vs O(n) for list, more efficient BFS queue
- **Separate `queued` set** — prevents duplicate URLs entering the queue from different pages
- **User-Agent header** — identifies the crawler ethically as `UniversityCrawler/1.0`
- **Non-HTTP links filtered** — `mailto:`, `javascript:` and anchor links ignored

### Indexer
- **Boilerplate removal** — `<script>`, `<style>`, `<nav>`, `<footer>`, `<header>` tags stripped before indexing to improve relevance
- **Case insensitive** — all tokens lowercased so `Good` and `good` are treated as the same word
- **Position tracking** — word positions stored for potential phrase search extensions
- **Document length tracking** — token count per document stored to support TF normalisation
- **JSON persistence** — human-readable, easy to debug, appropriate for this scale

### Search
- **TF-IDF ranking** — results ranked by relevance, not just presence
- **Normalised TF** — term frequency divided by document length to avoid long-document bias
- **IDF caching** — precomputed at startup to avoid redundant calculation per query
- **Query deduplication** — duplicate query terms removed before processing
- **Rarest-first intersection** — posting lists intersected in ascending document frequency order for efficiency
- **Query suggestions** — prefix-based word suggestions from the index

### Known Limitations & Future Improvements
- Stop words (the, is, to) are not removed — keeps the index transparent and complete
- Numbers are excluded from tokenisation — years and dates are not indexed
- Robots.txt not checked — acceptable as quotes.toscrape.com is a scraping sandbox
- Future work could add phrase search using stored positions

## Performance Benchmarking

### Build Performance
- Pages crawled: 213
- Total build time: recorded during video demonstration
- Each page takes around 6 seconds due to the politeness window, plus a small amount of time for the actual network request and HTML parsing
- The final index contains 4324 unique words across 213 pages

### Search Performance
All search operations are timed and shown directly in the terminal when you run a command. These are the actual times recorded on a MacBook:

| Operation | Time |
|---|---|
| `load` index from disk | 0.044s |
| `print` single word | 0.0010s |
| `find` single word (38 results) | 0.0010s |
| `find` multi-word query (3 terms) | 0.0010s |
| `suggest` prefix lookup | 0.0021s |

Every search completes in under 5 milliseconds. This is because the index uses dictionary lookups which are O(1), IDF scores are calculated once at startup rather than on every query, and multi-word searches always start with the rarest word to keep the result set small from the beginning.
